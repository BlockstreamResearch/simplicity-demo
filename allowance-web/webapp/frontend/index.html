Allowance contract Liquid testnet: demo, not real money

A benefactor deposits tLBTC once. A beneficiary can withdraw a limited amount, no more often than once every set number of blocks, until the balance runs out. This app runs the real, working tx-manifest-wallet engine behind the scenes, and every action here is a genuine, signed, broadcast Liquid testnet transaction.

What this contract actually enforces

  • The beneficiary can take up to the allowance amount, no more than once per the minimum block distance, by signing with their own key.
  • Each withdrawal either takes everything remaining (if the balance has dropped to the allowance amount or less) or takes exactly the allowance amount and puts the rest back into a fresh copy of the same contract, resetting its own clock.
  • Sending funds to the contract address a second time creates a separate, independent allowance instance, and it does not top up the first one. The two can never be merged.
  • Only explicit (non-confidential) funding outputs work. This app's Fund action always builds an explicit output correctly; a confidential output sent here by some other means would be permanently stuck.

How the wallet side actually works

This app is driven entirely by tx-manifest-wallet, a real, working, generic engine that reads a JSON manifest (examples/allowance/txmanifest.json in this project) describing the contract, and itself handles covenant compilation, UTXO selection, PSET construction, signing, and broadcasting. This app doesn't do any of that itself; it just gives you buttons instead of a command line.

Each installation of this app keeps its own local wallet file, used only by that installation. That's why the benefactor and beneficiary each see a "Your wallet" section: a real deployment has each party running their own copy of this app, so no server ever holds more than one party's keys.

Deploying for real (Liquid mainnet)

This demo only ever runs against Liquid testnet. See the project's mainnet notes for what would need to change to deploy for real. In short: real LBTC instead of a faucet, mainnet network parameters and explorer, and re-auditing the contract given real value is at stake.
